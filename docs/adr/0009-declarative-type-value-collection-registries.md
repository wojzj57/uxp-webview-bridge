# Declarative type/value/collection registries replace per-class decoder injection

The initial photoshop batch (Document/Layer/Layers) wired cross-object decoding by hand: the WebView namespace built one decoder closure per remote type (`documentDecoder`, `layerDecoder`, `layersDecoder`, `boundsDecoder`) in a `context` object, threaded it into every class factory, and attached it to individual descriptors as `decode: someDecoder`. The UXP host mirrored this with hand-written per-property maps (`LAYER_REF_PROPS`), one hard-coded value serializer (`serializeImagingBounds`), and one hard-coded collection serializer (`serializeLayersSnapshot` + `LAYERS_SNAPSHOT_KIND`). This works for three classes but does not scale to the full ps-reference DOM (~37 classes): the reference graph becomes dense and cyclic (`Layer.parent → Layer`, `Layer.document → Document`, `TextItem.color → SolidColor`, `Document.channels → Channels → Channel → Document`), and injecting one decoder closure per type into every other type's factory is O(N²) manual wiring that also deadlocks on construction order (factory A needs B's decoder, B's needs A's).

We therefore move to **declarative types resolved through central registries**, lazily, at the call site rather than at construction time. A property or method result declares only a **type name string** — `refType: "TextItem"` for a RemoteObject, `valueKind: "SolidColor"` for a value object, `collectionOf: "Channel"` for a collection — and decoding looks the target up in a registry when the reply actually arrives. Three registries, matching the three object kinds from ADR 0005:

1. **Type registry (RemoteObject):** every `RemoteClass` subclass registers itself under its remote type name. Envelope → instance decoding, and the host-side reference-property map, both derive from this registry instead of hand-maintained closures/maps.
2. **Value-object registry:** each value type registers once as `{ valueKind, fields }` (or a custom serialize/deserialize pair) in shared code. The host serializes by `valueKind`; the WebView decodes by `valueKind`. `ImagingBounds` becomes the first registered entry rather than a special case.
3. **Collection factory:** a single "snapshot collection" factory takes `{ memberKind, ownerRef, snapshotMethod }` and produces the WebView-local Array-subclass wrapper (ADR 0005), with `getByName`/`getByIndex`/`add` as per-collection opt-in capabilities. The host serializes any collection via one `serializeSnapshot(kind, memberKind)`.

This is a scoped evolution of ADR 0002's descriptor table — descriptors keep `writable`/`mutating`, but their result typing switches from injected `decode` closures to declarative `refType`/`valueKind`/`collectionOf` names resolved via the registries. The existing Document/Layer/Layers classes are migrated to the declarative form as part of landing this (RFC-0008), while only three classes exist and the migration cost is lowest.

## Considered Options

- **Declarative type names + central registries, lazy resolution (chosen):** Adding a class/value/collection is one registration plus a field list, not edits across three files. Lazy (call-site) resolution breaks the cyclic-reference and factory-order problems structurally. Host reference maps derive from the same registry, so the two sides cannot drift. Cost: one indirection (name → registry lookup) per decode; a migration of the three existing classes.
- **Keep per-class decoder-closure injection (status quo):** No refactor now. Rejected: O(N²) manual wiring across ~37 classes, construction-order deadlock on cyclic refs, and duplicate hand-written serializers/maps on both sides that drift independently. The cost only grows with each class.
- **One giant hand-written switch on type name (no registry):** Central but not extensible — every new class edits the central switch, and shared/webview/uxp each keep their own copy. Rejected: three switches to keep in sync is the drift problem in a different shape.
- **Runtime reflection over the live Photoshop object (host infers shape):** No declarations at all. Rejected: the WebView loses all static typing (ADR 0002's whole point), and property writability/mutating semantics can't be inferred from a live object.

## Consequences

- ADR 0002's "descriptor table + `declare`" and its static consistency test still stand; the change is that a descriptor's result type is now a declarative name, and the static test additionally asserts every referenced `refType`/`valueKind`/`collectionOf` name is present in the corresponding registry (no dangling type names).
- ADR 0005's three-kind classification (Value / RemoteObject / Collection) becomes the literal registry structure rather than an informal taxonomy: each kind has exactly one registry/factory, and "which kind is this type" is answered by which registry holds it.
- Value objects still need explicit per-type field lists (ADR 0005), but they live in one shared registry with a static test, not scattered hand-written serializers on each side.
- Cyclic references (`Layer.parent → Layer`, etc.) are supported without special handling because resolution is deferred to decode time; there is no construction-time dependency between class factories.
- Registration is a new required step per class/value/collection; a class that forgets to register, or references an unregistered type name, fails the static gate rather than at runtime.
- This is the mandated foundation for full ps-reference coverage; subsequent class batches (Channels, TextItem family, path/geometry, Selection, …) add registrations only and touch no central wiring.
